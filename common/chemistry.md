# 通用化学系统设计

状态：已注册物质的元素组成、单位质量化学能、元素守恒校验和反应能量差计算已实现。空气与非气体范围吸收已接入，见[世界物质设计](matter.md)；化学库存转化、器官额度分配和实际供能仍未接入。

## 已实现的计算基础

实现位于 `server/src/domain/element/chemistry.rs`，通过 `evaluate_reaction(registry, inputs, outputs)` 按实际输入、输出质量计算。每项数量使用 mg，包括气体；调用方必须先将气体库存体积换算成质量，不能直接传入 µL。

物质新增可选的 `chemistry` 数据，包含结构化 `atoms` 与 `chemical_energy_mj_per_mg`。元素采用 C=12、H=1、O=16、N=14 的整数相对质量。单糖使用现有 CH2O 经验单元，多糖使用 C6H10O5 重复单元；按质量计算时不依赖分子或聚合链长。

当前化学能为统一参考下的可调游戏参数，不是真实键解离能，也不是每 mg 食物的固定供能量：

| --- | --- | --- | --- |
| 碳 | C | 0 | 100% |
| 氢 | H2 | 0 | 100% |
| 氧 | O2 | 0 | 100% |
| 二氧化碳 | CO2 | -18.0 | 100% |
| 氮气 | N2 | 0 | 100% |
| 水 | H2O | -32.0 | 100% |
| 单糖 | CH2O | -14.0 | 100% |
| 二糖 | C12H22O11 | -13.0 | 80% |
| 多糖 | C6H10O5 | -11.0 | 50% |
| 纤维素 | C6H10O5 | -11.0 | 10% |
| 氨气 | NH3 | -5.4 | 100% |

| 通用脂类 | C18H36O2 | -6.6 | 25% |
| 结构蛋白 | C12H19N3O4 | -10.0 | 30% |

### 能量尺度与氧化收益

基础单质取零参考。内置物质统一使用原参考参数的 2 倍（上一版的 1/5），倍率位于 `builtin.rs` 的 `CHEMICAL_ENERGY_SCALE`，表中为实际注册值。器官能耗、反应额度、储能容量和处理速度不随倍率调整；改变的是能量密度，不是器官每 tick 输出上限。自定义物质的 `set_chemistry` 仍接收实际 mJ/mg，不自动乘倍率。

水 -32.0、二氧化碳 -18.0、脂类 -6.6 mJ/mg 参考相应生成焓的相对比例，再按游戏尺度缩放，约为真实生成焓绝对值的 0.2%。正确单位换算为 1 kJ/g = 1000 mJ/mg。这些是游戏参数，不模拟温度、压力或相变焓。脂类相对单质的生成能绝对值较小，不代表氧化供能较低；实际供能由反应两侧能量差决定。

以下按完全氧化到二氧化碳和水计算，单位质量指燃料本身，氧气质量另计。蛋白质行额外假设氮全部形成 N2，仅用于比较理论能量，不是已实现的排氮配方或实际修复收益。

| 燃料 | 理论释放能量 mJ/mg 燃料 | 耗氧 mg/mg 燃料 |
| --- | --- | --- |
| 碳 | 66.00 | 2.67 |
| 氢 | 288.00 | 8.00 |
| 单糖 | 31.60 | 1.07 |
| 二糖 | 33.32 | 1.12 |
| 多糖 / 纤维素 | 36.11 | 1.19 |
| 通用脂类 | 80.10 | 2.93 |
| 结构蛋白 | 45.67 | 1.75 |
| 膜蛋白 | 51.35 | 1.98 |
| 收缩蛋白 | 40.88 | 1.55 |
| 感知蛋白 | 40.55 | 1.58 |
| 角质蛋白 | 49.09 | 1.89 |
| 酶蛋白 | 36.06 | 1.35 |

例如 C + O2 → CO2，12 mg 碳释放 792 mJ；H2 + 0.5 O2 → H2O，2 mg 氢释放 576 mJ。按同样 32 mg 氧比较，碳释放 792 mJ，氢释放 1152 mJ；按燃料自身质量比较，氢更高是合理的，不能仅比较反应式的一次进度。

糖类约 32～36 mJ/mg、脂类约 80 mJ/mg，形成不同储能密度；纤维素与多糖的理论总供能相同，处理速度区分其吞吐量。处理速度不再乘到同一份已完成反应的理论总供能上。蛋白质统一使用 -10.0 的游戏初值，具体排氮产物确定后再核算实际代谢收益。

按标准状况参考密度 1.429 mg O2/mL、空气氧体积分数 21% 估算，5 mL 空气提供 1.50045 mg O2，支持 1.406671875 mg 单糖完全氧化，理论供能 44.45083125 mJ；同样的氧支持氢、碳、脂类分别释放约 54.02、37.14、41.03 mJ。每 mL 空气支持的单糖供能为约 8.89 mJ。这是平衡估算，空气组成及体积密度换算尚未实现。

吸气执行层现已改为按体积比例计费，5 mL空气需要基础3 + 可变5 = 8 mJ/tick，单糖理论剩余约36.45 mJ/tick，尚需扣除其他组件能耗。仅小型躯体的负向反应额度为10 mJ/tick，不能兑现全部供氧收益；安装反应结构I后合计60 mJ/tick，使用单糖时才有足够额度。低处理速度燃料仍受有效额度限制。实际代谢供能仍未接入。

```text
反应侧能量差 = Σ(输出质量 × 输出化学能) - Σ(输入质量 × 输入化学能)
自身储能变化 = -反应侧能量差
```

例如 2 mg 氢与 16 mg 氧转化为 18 mg 水：反应侧能量差为 -576 mJ，理论向自身供能 576 mJ；逆向需要输入 576 mJ。实际每 tick 能执行多少，仍需后续器官额度、处理速度、库存与储能容量约束，不能将计算结果直接当作无条件到账。

计算器不解析显示化学式，逐元素检查输入输出守恒；非法数量、未知物质、化学数据缺失和数值溢出返回错误。旧数据缺少 `chemistry` 时可继续加载，但参与计算时明确报缺失，不能将未知化学能当成零。相对浮点容差为 1e-9，无固定绝对容差，避免微量不守恒反应被放过。

计算器仅计算理论能量差，不应用初始处理速度或尚未定案的键能差效率公式，也不修改库存和自身储能。蛋白质的化学能暂统一使用 -10.0 mJ/mg 作为可调整的游戏初值。化学参数调优时应保留同一参考基准；正反反应能量差相反，分步与直接转化的理论总能量差一致。

## 基本规则

酶视为万能催化体系。只要物质组成满足通用反应的守恒条件，就可以直接转化为其他已注册物质，不要求固定消化链、指定中间产物或专门酶。

物质之间主要通过初始处理速度区分处理难度；器官提供有限的反应额度。产物由具体反应指定，物质定义不绑定产物列表。二糖、多糖、纤维素适用同一执行规则。

化学处理额度、有效反应进度、组件储能变化是三个不同的量，不能混用。

## 物质定义

新增通用字段：

```text
initial_processing_speed: 0.0～1.0
```

该字段是无量纲比例，表示分配的反应额度可以转化为多少有效处理量。旧物质和缺少字段的旧数据默认 1.0；拒绝非有限数和范围外数值。0 表示当前不能有效处理该物质，不能通过除法反推额度造成除零。

处理速度是独立的吞吐参数。现有名称、稳定 ID、类别、物理属性继续保留；元素组成和化学能另外通过 `chemistry` 保存，不能从显示名称猜测，也不能直接把显示式当成可靠的机器数据。

| 物质 | 稳定 ID | 初始处理速度 |
| --- | --- | --- |
| 单糖 | `monosaccharide` | 1.0 |
| 二糖 | `disaccharide` | 0.8 |
| 多糖 | `polysaccharide` | 0.5 |
| 纤维素 | `cellulose` | 0.1 |

纤维素与普通多糖可拥有相同元素组成，但保持不同物质 ID 和处理速度。

## 反应额度

沿用组件现有的 `reaction_min_mj_per_tick` 和 `reaction_max_mj_per_tick`。负向与正向分别有额度上限，各方向的总上限为有效组件对应额度绝对值之和。

当前参数：

| 组件 | 负向额度上限（反应向自身供能） | 正向额度上限（自身向反应供能） |
| --- | --- | --- |
| 小型躯体 I | 10 mJ/tick | 2 mJ/tick |
| 反应结构 I | 50 mJ/tick | 10 mJ/tick |

耐久为零的组件不贡献额度。部分耐久如何影响额度属于后续器官效率规则，不在本次引入第二种物质处理参数。

正负号以反应侧的能量流向为准：负向表示能量从反应处输出至生物自身，增加自身储能；正向表示自身向反应输入能量，消耗自身储能。它不是按分解或合成的名称分类，也不是自身储能变化的符号。

在反应实际完成、未再叠加其他损耗且不受储能容量限制时：

```text
自身储能变化 = -实际有效反应速率 × tick 时长
```

例如实际有效速率为 -4 mJ/tick 时，每个完整 tick 增加自身储能 4 mJ；为 +4 mJ/tick 时消耗自身储能 4 mJ。反应能量差决定具体转化是否能按该方向供能或吸能，不能任意指定方向制造能量。

同一生物的多个操作共享额度，不允许每条指令独占完整上限。反应结构 I 的 40 mJ/tick 是示例中分配的额度，不是把现有 50 mJ/tick 的负向上限改为 40。

## 处理速度结算

```text
有效处理速率 = 分配的反应速率 × 初始处理速度
已占用额度 = abs(分配的反应速率)
```

处理速度只缩放反应进度，不减少已分配额度。不能按有效处理量扣额度，也不能把未转化为有效处理的部分再次分配给其他反应。

分配 -40 mJ/tick 时：

| 物质 | 占用负向额度 | 有效处理速率 |
| --- | --- | --- |
| 单糖 | 40 mJ/tick | -40 mJ/tick |
| 二糖 | 40 mJ/tick | -32 mJ/tick |
| 多糖 | 40 mJ/tick | -20 mJ/tick |
| 纤维素 | 40 mJ/tick | -4 mJ/tick |

纤维素占用完整的 40，实际有效速率为 -4 mJ/tick。在底物充足、反应实际完成且储能可容纳的情况下，每 tick 向自身储能输出 4 mJ；其余 36 是本次占用中的处理能力损失，不另扣 36 mJ 储能，也不能再次分配。

若器官负向总额度为 50，分配 40 后只剩 10 可用于其他操作；若总额度为 40，则已占满。

同一反应涉及多种输入时，需要一个统一处理速度。建议第一版使用被消耗输入物质处理速度的最小值，表示最难处理的输入限制整次反应；该规则是待确认的通用选择，不是已确认要求。产物侧不再次乘处理速度，避免 10% 被重复乘成 1%。

## 通用反应表达

后续反应请求需要表达输入物质及比例、目标输出物质及比例、方向和请求额度，而不是限定为糖类水解等预设方法。具体 API 形式在接入时确定。

执行前由服务端验证：

- 所有物质已注册，数量和比例合法、有限且非负，反应有实际输入与输出。
- 输入和输出的元素组成守恒；相同元素组成可以对应不同物质，不能将它们合并为同一个 ID。
- 有可使用的反应额度，所需底物可访问，容器能容纳反应后的结果。
- 吸能反应具有足够储能；放能反应能按已定义规则存储或处理释放的能量。

不在物质定义中列出固定产物，也不要求先分解为基础元素再重新合成。守恒计算使用结构化组成数据；聚合物可使用明确的重复单元约定，不能依赖解析任意显示字符串。

## 有效处理量与物质量

mJ/tick 表示反应处理额度，库存使用 mg 或气体体积，两者不能直接互换。实际消耗多少物质，应根据反应的单位进度处理需求换算。

```text
本 tick 有效处理额度 = abs(分配速率) × 处理速度 × tick 时长
反应进度上限 = 有效处理额度 / 单位反应进度所需处理额度
```

单位反应进度所需处理额度必须为正，后续结合键能尺度定义。不能只使用净能量差的绝对值作为分母，否则净能量差为零的物质转化会得到无限吞吐量。

反应进度还受底物、容器、储能等限制。按最终同一份进度同时结算全部输入和输出，保持守恒；不各自对库存四舍五入。小数进度或余量持久化，确保低速反应不会永远被取整丢弃。

额度分配完成后，因处理速度降低产生的占用不返还；资源约束可先缩小可接受的分配量。最终被接受的分配量和执行进度应明确记录，便于录像和调试区分请求与实际执行。

## 键能差与能量收支

初始处理速度用于从分配额度得到有效反应速率；实际完成的负向反应向自身供能，正向反应消耗自身储能。键能差用于核算转化的能量收支与化合效率。不能因为处理速度是 10%，就在得到 -4 mJ/tick 后再次乘 10% 而只记入 0.4 mJ。

后续能量计算需要统一各物质化学能的参考基准和单位，不能把真实键解离能、游戏化学能与组件储能直接混为一谈。以统一参考的反应前后总化学能差决定吸能或放能，按实际反应进度结算，避免循环合成凭空供能。

原 `设计.txt` 给出的化合效率是：

```text
效率 = 1 - (n / 5)^3
```

该公式保留为待细化规则，尚未作为实现定案，原因如下：

- 需要定义 n 的尺度和方向；直接使用 x1/x2 时，正反反应得到不同倍率。
- 两侧相等、n=1 时效率为 0.992，不是 100%。
- n>5 时计算结果为负，实现时必须明确定义边界，不能生成负产量。
- 参考能量为零时，倍率除法需要另行处理。

化合效率的损失不能通过减少某种产物质量来破坏元素守恒。后续应明确为能量损失或可执行进度限制，并验证正反反应和阶梯式合成不会形成净能量收益。本次不以这条未完整定义的公式阻塞处理速度设计。

## tick 接入位置

未来在世界 tick 的统一执行阶段运行化学结算，与现有按世界原子提交一致：

1. 收集控制，验证并分配可用反应额度。
2. 根据输入物质处理速度计算有效额度，求资源约束下的反应进度。
3. 在状态副本中同时结算库存和储能，保存余量。
4. 保存并发布世界状态；保存失败不提交部分物质或能量变化。

吸收、化学、喷射之间的具体先后顺序由生存循环接入时统一确定，避免同一 tick 重复使用相同库存。化学不自行从任意远处容器取料，器官之间的物质可达范围也需由统一运输规则决定。

本次不新增世界食物配方、氧气需求或固定呼吸链。它们可以作为通用化学系统的使用方式另行设计。

## 实现边界

当前代码具备物质注册表、容器库存、器官反应速率属性、处理速度，以及组成和理论能量差计算。后续补齐反应进度、器官额度分配和库存/储能结算，再接入生存循环。

验证至少覆盖：100% 与 10% 的额度占用、多个操作共享预算、零处理速度、多输入速度只应用一次、零净能量差仍受吞吐限制、资源不足、满容器净转换、能量上下限、保存失败回滚和小数进度重启恢复。
